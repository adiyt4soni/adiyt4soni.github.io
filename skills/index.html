Skills and automations

A skill is a written procedure an AI agent loads whenever a task matches, so the same rules, order of steps and checks apply every time instead of being re-typed into a prompt. I turn work I keep repeating into skills, and then into scheduled automations where it pays to run on a timer.

I direct and review these; Claude or Codex wrote the text. Below: what each one does, where it came from, and the evidence that it has actually run.

Representative skills

Mine · Claude Code skill

jd-tailored-cv-and-letter

Builds one CV and one cover letter for one job ad, then tests them before anything is sent.

Inputs
A job ad, a fact bank of verified experience, the employer's own application instructions.
Process
A fresh agent writes the criteria from the ad alone and freezes them. Then an evidence map (direct, partial, unknown, gap), the CV and letter, six tests, and iterations against the same frozen list.
Controls
The writer never writes the criteria or grades its own work. An honesty check against the fact bank blocks shipping. Gates are pass or fail, never averaged.
Reuse
The same method runs in my job-search system: criteria files exist for 245 role folders. The skill packaging dates from 18 Oct 2026.
Limits
Coverage is scored by another AI instance, which is a separate review, not external confirmation. No link to interview outcomes yet.

Mine · Claude Code skill

independent-review-audit

Audits an automation or deliverable with a reviewer that didn't produce it.

Process
Acceptance checks are written before looking at results. The auditor gets the requirements and raw sources but not the original's explanation, checks key numbers by a different method, and proves each check can fail on a broken copy.
Controls
Read-only. 'An exit code of zero, or an assistant saying done, is not evidence.' Same-model review must call itself separate review, not independent confirmation.
Reuse
Codifies the October audit of my job-search system (see that case study), which found the gates were prompt-only.
Limits
Effectiveness depends on genuinely separate agents; no external auditor.

Mine · Claude Code skill

verified-research-run

Research where every fact is sourced and dated, and a separate skeptic checks each one.

Process
Finder agents propose with URLs from at least two kinds of source. A separate skeptical pass opens each live page and drops what fails, with a reason. Hard gates first, then an explained score.
Controls
Confidence tags on claims. A positive control before any 'nothing exists' claim. Blocked pages recorded as blocked, not as results.
Reuse
Same finder-then-skeptic method built my list of verified employers.
Limits
Depends on pages not being blocked; finder and skeptic may share a model family.

Mine · scheduled task

uk-daily-brief

A daily job-search brief that prepares the day's work and never submits anything.

Runs
08:05 daily. 43 runs from 8 Sep to 20 Oct 2026, one failed on a usage limit.
Controls
Scheduled runs never submit applications or send email; they stage drafts. State is written only through validated tools with backups.
Honest note
A run that finishes isn't always a clean run: the weekly scorecard flagged six runs in mid-October as partial, four because tracker writes were blocked. That's why the scorecard exists.
Limits
The published version is shorter than the live prompt, which contains personal context.

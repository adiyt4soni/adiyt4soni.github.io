Agent workflow In use

Job-search operations system

A system I designed and run with Claude Code to handle my own job search: it watches about 415 company job boards, screens roles against rules I wrote, builds and tests a tailored CV for each, and refuses to submit anything that fails its checks.

  • One sweep on 20 Oct 2026: 25,037 postings in, 4 sent on for an AI to read in full. Everything else was filtered by written rules
  • After a separate-session audit showed the rules lived only in prompts, I had them rebuilt as code with 150 automated tests
  • A pre-submit gate refuses duplicates, below-bar roles and banned content, and freezes the exact files sent

My part: I wrote the rules, asked for the audit, decided what changed, and nothing is submitted until I say 'apply'. Claude Code wrote the tools; Codex wrote and reviewed some of the prompts.

Research system Working locally

Argus 2.0

A research tool for testing whether an investment idea beats doing nothing, built to catch false positives. Rules and pass marks are written down before any test, the data tool refuses to let a test see information from after the decision date, and rejections are logged as results. Simulated trading only: no real money, and no code that can place an order.

  • Rebuilding the stock universe point-in-time turned an earlier +168% backtest into +34.5%, against +108% for simply holding the index
  • 7 rules rejected on pre-written criteria, and the first rule not promoted
  • The save command refuses an AI-written company note that contains a number or date not in the stored data

My part: I set the objective and the bar, decided what to test and when to stop, and chose between fixes when problems surfaced. Claude Code built the engine and ran the tests; Codex wrote the build specification.

Local AI assistant In testing

Vex

A personal assistant that runs on an open-weight model on my own laptop. What it may do is decided in code, not in its prompt, so it can't send, delete or read restricted files without my approval. From 13 to 19 October every change Claude Code wrote was reviewed by Codex before I decided whether it merged.

  • Codex flagged problems in 71 of 94 completed reviews in one week, counting re-reviews of fixes
  • The first review found that Claude's permission tests passed even with the permission gate switched off
  • A model comparison with pass marks written down beforehand ended with 'no model passes both gates; no switch'

My part: I own the charter and the safety rules, set what gets built first, accept or veto risk, and decide every merge. Claude Code wrote nearly all the code; Codex wrote an independent first version and runs the reviews.

Personal data analytics Working locally

Tau

A personal analytics app over my WHOOP wearable data. A scheduled pull feeds a rebuild that is checked by 21 validation tests, and the analysis only reports patterns that hold up after a check for chance. The screenshot shows my real dashboard; medical details are kept off this site.

  • Checking real data against a frozen reference caught a unit bug and a 12.5-hour timezone error that a synthetic test had missed
  • 0 of 25 tested habits held up after a check for chance, and the app says so instead of offering tips
  • The forecast is graded against a naive baseline and labels its own confidence

My part: I set the rules (no medical advice, nothing leaves the folder, check the output not the code), made the product calls and pushed back on the interface. Claude Code wrote and rebuilt the code and found both data bugs.

How I work with AI

The same loop runs through every project. Examples for each step →

  1. Define the problemWrite down what the system must do and what it must never do, before any code.
  2. Set constraintsPrivacy, cost and approval rules go into code where they can be tested, not into a prompt.
  3. Choose toolsPick the model, library or existing skill that fits, and record why.
  4. DelegateHand a written specification to Claude Code; keep each task small enough to review.
  5. ReviewA second model (Codex) reviews the change read-only; I decide which findings to act on.
  6. Test against evidencePre-registered checks, baselines and spot-checks against the source data.
  7. CorrectWhen a check fails, fix the cause and add a check so it can't recur.
  8. Accept or stopShip what passed; report nulls and stop what didn't earn its place.

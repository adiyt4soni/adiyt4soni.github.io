What it does

Tau pulls my data from the WHOOP API (sleep, recovery, strain and workouts), rebuilds a local dashboard of 13 pages, checks the rebuild, and writes a short daily analysis. A single scheduled routine runs it three times a day. A small command-line tool (tau pull, tau build --validate, tau brief) does each step, so every run is the same.

It also includes a read-only tool server (10 tools) that lets an AI assistant query the data without being able to change it. That server is built and tested locally; I haven't shown it connected to a live client.

Why I built it

The wearable's own app shows numbers but not whether a pattern is real. I wanted answers I could check. The original version was lost in a laptop migration in September, and only its output survived. That turned the rebuild into a test: the new code had to reproduce the old results, or explain why it couldn't.

My role and the AI's role

  • Me: the standing rules (the data never leaves the folder; it doesn't act as a clinician; verify the produced file, not the code that made it); product calls such as one routine instead of seven separate tasks, logging by text message, and moving credentials out of cloud sync; blunt feedback on the interface; and the one-time account sign-in.
  • Claude Code: wrote and rebuilt the code, built the validation harness, found both data bugs, and documented every change.

The interface pass on 24 September came from my complaints: dead clicks, dead date arrows, clutter. The cause turned out to be event handlers lost on every re-render, fixed with one shared handler.

Mistakes caught

  • A synthetic test passed; real data failed. The first test fixture was built from the same assumptions as the code, so it agreed with the code. The first live pull exposed two defects it could not see: one metric was off by a factor of 1,000, and the token endpoint blocked the default Python user agent. Lesson: a test made from your own assumptions isn't a test.
  • A 12.5-hour timezone error in the old data. Joining the raw export to the API's day boundaries showed that the original pipeline read every local time as Indian time. Re-injecting exactly that error reproduced the old estimate to six decimal places, which proved the cause. The bug had also produced a false nine-day anomaly.
  • Circular validation avoided. An early harness compared the rebuild with its own current output and reported 12 of 12. It now compares against a frozen copy of the original.

How it was checked

  • 21 validation checks on every rebuild: 13 recompute a derived block and compare it with the frozen reference; 8 test individual modules. The recorded run on 18 Oct gave 14 exact, 4 within tolerance, 3 different (explained), 0 errors.
  • Mutation tests: deliberately breaking a lag, a threshold or a timezone offset makes the matching check fail and name the field.
  • Statistics with correction: each habit-versus-sleep question gets a confidence interval and a false-discovery-rate correction. On the September data, 0 of 25 survived. Text that used to present raw averages as personal levers now goes through a gate that only quotes effects that survive.
  • Forecast against a baseline: a walk-forward model is compared with simply predicting 'same as yesterday'. It calls its confidence 'moderate' only when it beats that baseline by 10% or more, and never 'high'. The rebuilt model did worse than the lost original on the frozen period, and the app says so.

Limits

  • One person's data: these are personal checks, not clinical findings, and Tau gives no medical advice.
  • Some statistical shortcuts are still open and listed in the project: the bootstrap treats days as independent, and the forecast has only one baseline.
  • The one pre-registered experiment was stopped partway through by a change in my routine, so it never produced a verdict.
  • No version control, so who introduced the unit bug (old pipeline or first rebuild) can't be settled.

What's shown here

The dashboard screenshot is real and shows a little of my own data, by my choice. Medical details stay private. For a fuller demonstration without personal data, the plan is a synthetic generator that writes fake records in the WHOOP format, plants known faults (a ×1000 unit error, a constant timezone shift, 25 habits with no real effect plus one planted effect), and shows the real pipeline catching each one. That generator isn't built yet.

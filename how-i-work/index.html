How I work with AI

AI writes most of the code in my projects. What I bring is the order things happen in, the rules they follow, and the checks they have to pass. Each step below links to where it happened.

1. Define the problem before the tool

I write down what the system must do, what it must never do, and what 'done' looks like. For the job-search system that became a written rulebook with named gates and tiers, amended and dated whenever my scope changed. For Tau I began with standing rules. The data never leaves the folder. It gives no medical advice. And I check the produced file, not the code that made it.

Examples: job-search rules, Tau's rules.

2. Put constraints where they can be tested

A rule in a prompt is a request; a rule in code is a control. A separate-session audit in October showed my screening gates existed only as prompt text, and 61 of 98 submissions slipped past them. The fix was a pre-submit check in code, with tests that prove it refuses what it should.

Example: the audit that changed it.

3. Choose tools on evidence

  • I picked an open-weight model that fits my laptop, and dropped an idea once it was shown to be impossible (archive).
  • When a cheaper model scored identical CVs far lower than a stronger one, the scoring stayed on the stronger model (job-search system).
  • I reuse other people's skills with credit rather than rewriting them (skills library).
  • Before extending Tau, a research pass compared 28 similar open-source apps and concluded build, don't fork.
  • My toolkit: Claude Code and Codex for building and review, VS Code with GitHub Copilot (which I used alongside Claude for my earlier projects, VexOS and the first Argus), and Ollama for local models.

4. Delegate in small, checkable pieces

Claude Code does most of the building. I hand it a specification, not a wish, and split large work into lanes run by separate agents. Repeated work becomes a skill, so the same steps and checks happen every time. For example, criteria are always frozen before a CV is written (skill). Routine runs go on a schedule with hard limits: they never submit applications or send email.

5. Review with a second model, and say what that proves

On Vex, from 13 to 19 October, every change Claude Code wrote was reviewed by Codex, a model from a different company. It ran read-only against a pinned commit, with a brief to break specific claims, and a script checked Codex's own session record before a review counted. 71 of 94 completed reviews ended with a negative verdict, counting re-reviews of fixes.

Earlier, the very first review (6 Sep) had found tests that passed with the safety gate switched off. A later one found a privacy bypass introduced by a fix.

A second model gives a separate review, not an independent guarantee, and I label it that way. (Vex project)

6. Test against evidence, with baselines

  • The job-search screen was compared with blind judges and a rules-only baseline, and the limits of that comparison are stated (how it was checked).
  • Tau's forecast is graded against 'same as yesterday', and its statistics only report effects that survive correction (Tau).
  • Any claim that something doesn't exist needs a positive control: proof the search can find that kind of thing at all. Separately, Tau's synthetic test passed while real data failed, which is why real data is the reference.

7. Correct the cause, then add a check

When something goes wrong I want the check that would have caught it, not just the fix:

  • the unit bug in Tau now has a validation check;
  • the missed 'Chief of Staff' and Leeds cases are now regression tests;
  • an AI honesty audit of my evidence notes found 8 of 84 claims stronger than the record. They were reworded, and wording that failed earlier audits now sits on a block list.

8. Accept, report nulls, or stop

Things ship when they pass, and stop when they don't:

  • 0 of 25 effects in Tau survived correction, and that's what the app says.
  • The 'brain' map turned out to be a viewer, not a token saver, so its README says that.
  • Unfinished work is labelled in the archive rather than left out.
